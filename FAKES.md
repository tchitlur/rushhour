# FAKES.md — every shortcut, how it works, how to explain it honestly

Nothing here invents real-world facts. Events and weather are real and sourced. The simulator computes every number shown.

| What | How it's done | How to explain it |
|---|---|---|
| **The restaurant and its history are synthetic** | "Maria's Burgers & Wings" is fictional. Menu, prices, food costs, prep times, staff, wages and the baseline orders-per-hour curve are hand-set, seeded constants (`src/sim/scenario.ts`). The UI carries the label "Demo restaurant · synthetic history · real events & weather". | "The restaurant is a demo persona. A real merchant would plug in their POS history and menu; the engine takes those as plain data." |
| **Curveball presets are pre-written patches** | The four curveball buttons and six likely judge questions map to hand-written `ScenarioPatch` objects (`src/data/ask-cache.ts`) in exactly the schema the LLM produces. Free-text questions go to the LLM live (`/api/ask`), with a keyword translator as fallback if the LLM is slow or down. | "Presets are cached translations so they're instant; type anything else and you'll see the live translation (the chip says 'AI-translated' vs 'preset')." |
| **Cached AI proposals for the demo night** | `src/data/plan-cache.json` holds a real OpenRouter (Claude Sonnet) response for Nov 13. Rehearse tries the live LLM first (7 s budget in demo mode); if it fails it uses this cache and labels the source. Rule-based proposals are always merged in as extra candidates. | "The AI is live; if the Wi-Fi dies, it falls back to its own earlier answer, and the simulator still tests everything." |
| **Rule-based proposer** | `src/plan/rules.ts` always generates staple candidates (call in Ana, par-cook wings/fries, longer quote, pause Uber Eats, reassign, move fryer) plus one deliberately weak idea (par-cook salad) so the "rejected" state is exercised. | "The LLM isn't required for the planner to work; the simulator is the judge either way." |
| **Dollars at risk** | Expected refunds/error charges: cold order = 50% of order value, late = 15%, wrong-order probability rises with kitchen load (1.5%–25%) at 50% of value, lost (balked) order = 60% of an average $22 ticket, unfinished at close = $11. Calibrated to DoorDash's published 25–100% error-charge range, not to real merchant data. | "It's an expected-value estimate with documented weights, not a bill." |
| **Reassign-worker intervention** | The engine has no time-windowed skills, so reassigning scales the worker's station skills for the whole night (+25% at the target station, −15% elsewhere). The card says so. On the demo night the simulator rejects it. | "An approximation; the simulator still gets a vote." |
| **Representative playback night** | The Watch/Race playback uses the one seeded night whose dollars-at-risk is closest to the 300-night mean (not the worst night, not a cherry-picked one). Headline numbers come from the 300-night means. | "You're watching the median night; the stats are over 300." |
| **Weather "rain" what-if** | The real Nov 13 forecast is fog with a chance of light snow, not rain. Rain exists only as a clearly labeled what-if toggle. | "We don't fake weather. Rain is a toggle you can turn on." |
| **Event explanations** | The one-liners under each event card come from the LLM given only the structured fields; if it doesn't answer within 6 s a template sentence is used instead. | "Explanations are generated from the card's fields; the numbers never come from the model." |
| **Lost conversion from longer quotes** | Modeled as 0.6% fewer delivery orders per extra quoted minute × $22 × 65% margin in the window (`src/plan/cost.ts`). Not from real data. | "A documented assumption that penalizes over-quoting." |
| **3D labels need the network** | The 3D view loads a font from a CDN for labels. If offline, labels can go blank; the 2D view (default) has no such dependency. | Use 2D if the venue Wi-Fi is bad. |
